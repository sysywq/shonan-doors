# Facebook共有画像と記事写真の一致

スクリーンショット対象: 記事272「第50回ひらつか民俗芸能まつり」。記事画面は /assets/images/category-photos/event.webp、共有メタデータは旧 /assets/ogp/festival.png を指定していた。単なるFacebookキャッシュとは断定せず、まず実際に異なる画像を指定していた生成処理を修正。

- build_ogp_image_url は記事画面と同じ resolve_article_hero_image を使う。記事固有画像がある場合はその写真、ない場合は現在のカテゴリ写真を使う。
- OGP、Twitterカード、構造化データを同じ画像URLへ統一。相対URLを絶対化し、既存の絶対URLを二重連結しない。
- 旧イラスト用の固定1200x630メタデータは削除。写真の寸法を捏造しない。
- Facebook投稿直前の公開チェックをHTTP 200だけでなく、配信HTMLのog:imageと記事上の写真と現在の元データの画像指定の一致まで確認するものに変更。古いビルドや欠落・二重指定なら投稿を見送る。
- 公開済み187記事を再生成し、全件で写真指定の一致をローカル確認。

本PRは修正準備のみ。本番へのマージ・Facebookへの再投稿・既存投稿の削除・添付差替え・再スクレイプは行っていない。ユーザーの本番反映保留を維持する。

反映後はMeta Sharing Debugger等で既存URLの再取得と、投稿済みカードでの画像反映を確認する。サイトのタグ修正だけで既存の全投稿画像が直ったと扱わない。Graph APIを使った既存投稿の添付差替えは実APIで確認できていないため、今回未検証の更新呼び出しを追加しない。
